## 1. Manual Check Call Graph (actual repository path)

```text
/vacprobe <player> | /vac check <player>
  -> ClientProbeCommand.onCommand / check
     (platform/paper/ClientProbeCommand.java)
  -> CheckHacksClientDetectionModule.check
     (detection/probe/CheckHacksClientDetectionModule.java :: startCheck, onlyIfIdle=false)
  -> DetectionSession created (UUID sessionId, target UUID)
  -> runPass INITIAL, batches of <=3 probes
  -> PaperSignProbeTransport.send per batch
     (platform/paper/PaperSignProbeTransport.java)
  -> sign place (region scheduler) -> NMS block-entity + open-editor (entity scheduler)
  -> SignChangeEvent -> ProbeResponse(RESPONSE) | timeout -> TIMEOUT
     | quit/error -> DISCONNECTED/ERROR
  -> CheckHacksResponseEvaluator.evaluate per probe line
     (detection/probe/CheckHacksResponseEvaluator.java)
  -> flagged = INITIAL DETECTED or PROTECTED
  -> if flagged non-empty and double-check=true: runPass CONFIRMATION on flagged only
  -> complete(session, aggregate(second|first))
  -> DetectionResult(status, reason, evidence with pass=INITIAL|CONFIRMATION,
     classification=CLEAN|DETECTED|PROTECTED|ERROR, probe=id, session=id, trigger=MANUAL)
  -> EnforcementService.enforce (single shared instance for manual AND automatic)
     (enforcement/EnforcementService.java)
  -> DefaultEnforcementPolicy.decide: KICK only if ConfirmedDetection.isConfirmed
     (status==DETECTED AND some evidence pass=CONFIRMATION classification=DETECTED)

     | duplicate session key -> NONE | else KICK via PaperEnforcementExecutor
  -> ClientProbeCommand.report: log + player message with status/action/reason/mods/session
```

Manual and automatic checks share the same `EnforcementService` instance
(created once in `VAntiCheatPlugin.onEnable` and passed to both
`ClientProbeCommand` and `AutomaticClientDetectionListener`). Verified by code
inspection, not assumption.

## 3. Player B (manual DETECTED -> NOT kicked)

`DETECTED` on screen is the **final session status**, not proof of a kick.
A final `DETECTED` with `action=NONE` is produced by exactly one of:

| # | Cause | Distinguisher in new output/logs |
|---|-------|----------------------------------|
| A | Trusted UUID bypass | `action=NONE reason=trusted player bypass`, status stays `DETECTED` |
| B | `PROTECTED` misread as detected | `status=PROTECTED` (timeouts and some key-equals responses map here), never kicks |
| C | Offline at enforce time | `action=NONE reason=target offline or kick unavailable` |
| D | `enforcement.enabled=false` in `config.yml` | `action=NONE`, policy disabled |
| E | Duplicate enforcement of same session | `action=NONE reason=enforcement already applied` (second enforce of identical session key) |

## 7. Root Causes (production defects found)

1. **Manual output ambiguity.** `probe.result` showed only `status` and
   evidence count, hiding `action`, `reason`, `mods`, and `session`. A
   trusted bypass, an offline target, a `PROTECTED` verdict, and a confirmed
   kick were indistinguishable on screen. Fixed by extending the message and
   server log with `action=`, `reason=`, `mods=`, `session=`.
2. **Silent automatic skip paths.** `offline-before-start`,
   `session-already-active`, and `duplicate-or-busy` completed the
   coordinator without any terminal log line, so a join with visible signs
   followed by a skip looked like "no result". Fixed with explicit
   `AutoCheck COMPLETE ... result=SKIPPED reason=...` logs.
3. **Missing session correlation in auto logs.** `RESULT`/`ENFORCEMENT` lines
   had no session id, making A/B/C parallel sessions untraceable. Fixed by
   extracting the evidence `session` id into every auto lifecycle line:
   `START`, `RESULT`, `ENFORCEMENT`, `COMPLETE`.

No detection, probe, priority-map, or enforcement-policy semantics were
changed. Timeout still maps to `PROTECTED` (existing evaluator contract);
that mapping is now documented instead of silently conflated.

## 10. Remaining Limitations

- All 29 configured probe keys remain `UNVERIFIED`; a wrong key yields
  `CLEAN` on both vanilla and modded clients (most likely Player C
  explanation if transport evidence shows responses arrived).
- `TIMEOUT` maps to `PROTECTED`, never to a distinct `TIMEOUT` final state;
  the vocabulary has no `TIMEOUT`/`CANCELLED` `DetectionStatus`.
- `messages.yml` on existing servers is not auto-migrated (`saveResource`
  does not overwrite); old files lack `%mods%`/`%action%` until regenerated
  or edited, then `/vac reload`.
- `xaeros-minimap` remains disabled per the P12 false-positive rule and is
  excluded from both manual and automatic execution.
