# P12.6 Configuration Hardening

## Root Cause

The previous Folia warning was caused by a manually modified test-server
`client-detection.yml`. The bundled repository configuration parses
successfully; no defect was found in its boolean values.

The loader did have an operational weakness: it converted every parse failure
into an indistinguishable disabled configuration. P12.6 makes that failure
explicit without changing the bundled probe policy.

## Valid Format

Boolean fields must use YAML booleans, not quoted strings or numbers:

```yaml
client-detection:
  enabled: true
  double-check: true
  auto-check:
    on-join: true
    first-join-only: false
```

`enabled: "true"`, `enabled: 1`, and `enabled: 0` are rejected. No legacy
representation was present in repository history, so they are not accepted.

## Invalid Configuration

Strict validation reports the file, exact configuration path, expected type,
and detected type, for example:

```text
file=client-detection.yml
path=client-detection.auto-check.on-join
expected=boolean
actual=String
```

At startup, invalid client detection is explicitly reported as
`clientDetection=UNAVAILABLE reason=INVALID_CONFIG`; no automatic check is
registered and `/vac check` reports that detection is unavailable. It is never
reported as a clean result.

## Reload Semantics

`/vac reload` validates `client-detection.yml` before unregistering listeners
or shutting down the running core. If validation fails, the command reports
failure and the last known-good runtime remains active. If validation succeeds,
the normal plugin reload applies the new configuration.

`saveResource(..., false)` continues to preserve an existing user file. A
fresh installation receives the bundled file; an existing file is not
overwritten.

## Probe Policy

The bundled configuration still contains 29 definitions. Meteor remains
enabled with:

```text
key.meteor-client.open-gui
```

`xaeros-minimap` and `xaeros-worldmap` remain disabled and excluded from
automatic selection. No detections or probes were added or re-enabled.

## Other Systems

Trusted Players and the Lunar Apollo policy are unchanged. Lunar remains a
non-enforcing policy integration: Apollo registration disables only the Lunar
Minimap and never classifies or kicks the player. Real Lunar GUI validation is
still unavailable.

## Validation

P12.6 tests cover fresh/current config loading, preservation of an existing
file, strict boolean errors, probe integrity, Meteor, Xaero, automatic join
configuration, and the existing Lunar/Trusted Player regressions. Live Paper
and Folia instances were unavailable for this gate.
