# P3.4 Positive Detection Enforcement

## Policy

Only a terminal `DETECTED` result containing confirmation-pass evidence with a
`DETECTED` classification is eligible for enforcement. Initial detections,
clean results, errors, timeouts, protected results, uncertain results, and
skipped results do not kick.

The default confirmed-detection action is `KICK`. It is configurable with:

```yaml
enforcement:
  enabled: true
  confirmed-detection:
    message: "Cheating detected."
```

## Architecture

`EnforcementService` is platform-neutral. `DefaultEnforcementPolicy` decides
whether a result is eligible, while `EnforcementExecutor` performs the
platform operation. Paper supplies `PaperEnforcementExecutor`; it checks that
the target is still online before calling the Bukkit kick API.

The service is idempotent per player UUID and adds a `SYSTEM` evidence record
with the resulting action and reason. If the player disconnects before the
action is applied, the confirmed result is retained and no kick is attempted.

## Verification Status

Deterministic unit coverage verifies confirmed kick, duplicate callbacks,
disabled enforcement, offline targets, initial-only detections, and all
non-punitive terminal statuses. A real supported modded-client positive
detection and live kick remain `UNVERIFIED` until such a client is available.
