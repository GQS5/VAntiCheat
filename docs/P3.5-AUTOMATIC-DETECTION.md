# P3.5 Automatic Detection and Production Enforcement

## Automatic Flow

```text
PlayerJoinEvent
  -> AutomaticCheckCoordinator
  -> one-tick entity-safe delay
  -> CheckHacksClientDetectionModule
  -> configured initial probes
  -> confirmation when required
  -> DetectionResult
  -> EnforcementService
```

The join listener does not contain probe or kick logic. It only applies join
configuration, creates the platform target, and delegates to the existing
module and enforcement service.

## Configuration

Automatic checking is configured in `client-detection.yml`:

```yaml
client-detection:
  enabled: true
  auto-check:
    on-join: true
    delay-ticks: 1
    first-join-only: false
    max-concurrent: 32
    probes:
      - meteor-client
      - freecam
```

`client-detection.enabled` controls the client detection module. The
`auto-check.on-join` setting controls only the join trigger. Enforcement is
configured independently in `config.yml` through `enforcement.enabled`.

The automatic probe list selects existing configured CheckHacks-derived probe
IDs. Unknown IDs are ignored and disabled probe definitions are excluded.

## Session Protection

The detection module owns one active session per player UUID. A manual check
and an automatic check cannot run concurrently for the same player. A join
check that encounters an existing module session is skipped.

`first-join-only` uses Bukkit's persistent `Player.hasPlayedBefore()` state;
there is no unbounded in-memory UUID set and no database.

The coordinator also protects delayed join tasks against duplicate join events,
reconnect races, quit-before-start, and plugin shutdown.

## Concurrency

Automatic checks are bounded by `max-concurrent`, defaulting to 32 pending or
active players. When the limit is reached, the new check is skipped and a
warning is logged. There is no unbounded queue.

## Enforcement Semantics

Only a final `DETECTED` result containing confirmation evidence classified as
`DETECTED` can invoke the default kick policy. `CLEAN`, `PROTECTED`,
`UNCERTAIN`, `ERROR`, timeout, skipped, transport failure, and disconnect
results do not kick.

The Paper executor performs the kick immediately from the result callback. The
result remains confirmed if the player disconnects before the executor can send
the kick. Enforcement evidence includes the action, reason, and confirmation
probe where available. Enforcement is idempotent for a detection session, but
a reconnect with a new session can be checked again.

## Evidence and Logging

Automatic probe evidence has `trigger=JOIN`; manual evidence has
`trigger=MANUAL`. Existing session, pass, probe, transport, and classification
metadata are retained. Normal logs report scheduling, start, confirmed
detection, and kick actions. Packet-level details remain behind the existing
debug setting.

## Bedrock and Geyser

No Geyser or Floodgate dependency is added. The current architecture does not
reliably identify Bedrock clients, so it does not guess or kick based on that
identity. Bedrock-specific handling remains a future integration.
