## Scope

and enforcement-isolation scenarios. No production source changes were made in

## Mixed Clean/Modded Paper Run

**PASS for enforcement isolation; clean classification had an error outcome.**

`CleanMix` and `XaeroMix` joined the same Paper 1.21.11 server. `CleanMix`
received `outcome=ERROR`, `status=ERROR`, and `decision=ALLOW`; it was not
kicked. `XaeroMix` completed confirmation with:

```text
status=DETECTED confirmationProbes=[xaeros-minimap]
Confirmed detection: XaeroMix - Action: KICK
Enforcement: KICK XaeroMix
```

The clean player was not incorrectly enforced while the positive player was
kicked. The full evidence is in `/home/shadi/test-server-paper/server-p3.8-paper.log`.

## Rapid Join and Configured Limit

**PASS for rapid-join stability; live skip-at-limit remains unverified.**

The 33-client burst used the live `max-concurrent: 32` configuration. All 33
automatic checks were scheduled because the configured probes completed quickly
enough for admission slots to recycle. Therefore this run did not produce a
live `concurrency limit reached` skip. The skip policy remains covered by the
deterministic `AutomaticCheckCoordinatorTest` test.
